## 关键决策点

### 1. 视图矩阵选择
```
+Y和-Y面的Up向量为什么不同？

+Y面（看向上）:
  目标: (0,1,0)
  需要右向量: (1,0,0)
  所以Up = (0,0,1) ✓

-Y面（看向下）:
  目标: (0,-1,0)
  需要右向量: (-1,0,0)
  所以Up = (0,0,-1) ✓

其他面都用(0,-1,0)作Up
```

### 2. Multiview vs 6次渲染
```
Multiview方案:
  ┌─────────────────────┐
  │ 单次RenderPass      │
  │ ├─ 6个视图同时渲染  │
  │ └─ 结果: 6个面      │
  └─────────────────────┘
  性能: ⭐⭐⭐⭐⭐

传统方案:
  ┌─────────────────────┐
  │ RenderPass 1 (+X)   │
  ├─────────────────────┤
  │ RenderPass 2 (-X)   │
  ├─────────────────────┤
  │ ...                 │
  ├─────────────────────┤
  │ RenderPass 6 (-Z)   │
  └─────────────────────┘
  性能: ⭐⭐
```

### 3. 布局转换时机
```
渲染完成
    ↓
COLOR_ATTACHMENT_OPTIMAL
    ↓
[必须转换！]
    ↓
SHADER_READ_ONLY_OPTIMAL
    ↓
可被采样
```

## 内存流向

```
CPU                          GPU
 │                            │
 ├─ UBO数据 ─────────────────→ globalBuffer
 │                            │
 │                            ├─ 顶点着色器
 │                            │  ├─ 读取viewproj[gl_ViewIndex]
 │                            │  └─ 计算gl_Position
 │                            │
 │                            ├─ 片段着色器
 │                            │  ├─ 采样纹理
 │                            │  └─ 输出颜色
 │                            │
 │                            └─ 写入cubemap
 │                               (6个面)
 │
 ├─ 等待完成 ←─────────────── 渲染完成
 │
 ├─ 读取cubemap ←────────────── 转换布局
 │
 └─ 保存到文件
```
